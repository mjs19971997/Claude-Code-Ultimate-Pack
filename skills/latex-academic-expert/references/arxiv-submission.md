# arXiv Submission

Reference for preparing a LaTeX source package for arXiv. Verified against arXiv's TeX submission help, its TeX Live FAQ and 00README documentation as summarised in 2026-10: arXiv offers TeX Live 2025 (default) and TeX Live 2023; arXiv has said it intends to follow annual releases and offer the newest two. Rules change; read the linked pages on the day of submission.

## 1. What arXiv does with a source package

- You upload a `.tar.gz`, `.zip` or single files (TeX source, figures, class and style files, `.bbl`). arXiv compiles the source itself for TeX submissions; upload the source rather than a PDF when the paper was written in LaTeX.
- arXiv runs the compile on its own TeX Live installation, so a package that builds on your machine can still fail on theirs if a package version or file differs.
- arXiv publishes the source. Everything in the package, including TeX comments and unused files, becomes downloadable.
- Ancillary files (data, code, supplements) go in a directory named `anc` at the root of the package; they are available separately and never compiled.
- Check current limits on submission size, number of files and ancillary file size in arXiv's own help pages; third-party figures vary and are not reliable.

## 2. TeX Live version

- arXiv provides the two latest versions it has deployed; at the time of verification these were TeX Live 2025 (default) and TeX Live 2023. The version is stored per submission as `texlive_version`, chosen at upload (and settable in `00README.json`).
- arXiv has stated that when TeX Live 2026 arrives, submitters will choose between 2025 and 2026 and 2023 will be dropped. Whether this has happened is not confirmed here; check the submission page and the TeX Live FAQ.
- Match your local or Overleaf TeX Live version to the one you select on arXiv. Overleaf notes that arXiv and Overleaf both used compatible TeX Live 2025 builds as of early 2026, with possible differences for packages updated between 2025-08-03 and 2025-10-27.
- Newly released class or package updates may exist in your TeX Live but not in arXiv's: do not rely on the very latest feature of a package; vendor the needed `.sty` or `.cls` into the package instead, unless it is a biblatex main file (see section 3).
- Compile settings in Overleaf (compiler and TeX Live version) are not carried over; copy them into the arXiv upload dialog or `00README.json`.

## 3. Bibliography and the bbl file

- BibTeX: arXiv runs `bibtex` when it detects no biblatex. Including the `.bbl` file produced by your own build guarantees an identical reference list.
- biblatex: arXiv detects biblatex and runs the backend set in the biblatex options (`biber`, `bibtex` or `bibtex8`). Since late 2025 arXiv accepts submissions without a `.bbl` when every needed `.bib` file is included.
- The conservative, reproducible choice is to upload the `main.bbl` produced by the same biblatex version arXiv uses together with the `.bib` file, and to keep the `.bbl` unmodified (named exactly after the main TeX file).
- Other processors (for example `upbibtex`) require a precompiled `.bbl`.
- Do not upload a local copy of `biblatex.sty` or its `.def` files. A stale copy causes errors such as `Patching \MakeUppercase failed`; the fix upstream is biblatex 3.18b or later, but removing the local copy is simpler.
- A warning about the wrong `.bbl` format version means the file was generated by a different biblatex release than arXiv's; regenerate it with the TeX Live version selected on arXiv.
- The `.bbl` must correspond to the final text; regenerate it after the last citation change. Check that `\bibliography{...}` and the `.bbl` agree.

## 4. 00README

- In the current submission system arXiv builds `00README.json` automatically from your upload; classic `00README.XXX` files are converted to JSON at the "Review Files" step. The format also accepts YAML.
- Documented top-level keys include `spec_version` (currently 1), `texlive_version`, `stamp` (arXiv watermark, default true) and `nohyperref`.
- A `process` block holds the `compiler`, and a `sources` list gives each file a `usage` of `toplevel`, `include` or `ignore`. Mark the main file `toplevel`, files compiled via `\input` as `include`, and files that must be present but not compiled (for example a standalone figure source) as `ignore`. Exact compiler values and extra keys: check the current 00README page.
- Use it to select the main file when the package holds several `.tex` files, to choose the compiler, and to pick the TeX Live version.
- Keep the file small and in sync with the package; edit it in the web UI rather than guessing unsupported keys.

## 5. File names and figures

- Use only letters, digits, hyphens, underscores and dots in names; no spaces or other symbols. Names are case sensitive on arXiv (`Fig1.PDF` is not `fig1.pdf`), and the TeX source must match exactly.
- Use relative paths in `\includegraphics` and `\input`. Absolute paths do not work. `\graphicspath{{figures/}}` is fine.
- With the PDF route, figures must be PDF, PNG or JPG. EPS and PS are for the classic DVI route only. arXiv does not convert formats for you; convert before upload (`epstopdf`, `pdfcrop`, `rsvg-convert` for SVG).
- Do not put TeX files in the `anc` directory.
- Avoid embedded JavaScript in PDF figures; it causes the submission to fail.
- Keep the main file at the package root with a plain name (`main.tex` or `paper.tex`); keep the number of files low by flattening nested directories where practical.
- Do not rely on `-shell-escape`: packages that need it (`minted` without prebuilt cache, TikZ externalisation) fail on arXiv. Pre-render the output and include the result.

## 6. Source clean-up

- Strip comments: arXiv publishes them. A script can remove full-line comments, or use `arxiv_latex_cleaner` (a third-party tool; review its output before upload).
- Remove build products that were not requested: `.aux`, `.log`, `.out`, `.toc`, `.synctex.gz`, editor backups. Keep `.bbl` as described above.
- Remove files that are not used: old figures, drafts, `todonotes` leftovers. Unused files add size and leak content.
- Remove review-only aids: line numbers, `\usepackage[draft]`, colour highlights, author-identifying notes.
- Check `\hypersetup` for `pdfauthor` and similar fields you do not want in the PDF; arXiv adds its own watermark through the `stamp` setting.
- Never include API keys, tokens, internal paths or email threads in any file; the source package is public.

## 7. Packaging script

Create the archive from a clean tree, then test it in an empty directory:

```bash
set -euo pipefail
latexmk -pdf -interaction=nonstopmode -halt-on-error main.tex
mkdir -p submission
cp main.tex preamble.tex main.bbl refs.bib submission/
cp -r sections figures submission/
tar -C submission -czf arxiv.tar.gz .

rm -rf /tmp/arxiv-test && mkdir /tmp/arxiv-test
tar -C /tmp/arxiv-test -xzf arxiv.tar.gz
(cd /tmp/arxiv-test && latexmk -pdf -interaction=nonstopmode -halt-on-error main.tex)
```

Replace the paths with the actual layout. Compile the unpacked copy with the same TeX Live version selected on arXiv (a container tagged to that year is the most reliable).

## 8. Pre-upload checklist

- [ ] Main file compiles from an empty directory with the arXiv TeX Live year; log has no `undefined` messages.
- [ ] `.bbl` regenerated after the last citation change and named after the main file; `.bib` included if the arXiv build should rerun the bibliography tool.
- [ ] No local copy of `biblatex.sty`, `hyperref.sty` or other TeX Live packages unless intentionally patched.
- [ ] File names ASCII, no spaces, case matches the source.
- [ ] Figures PDF, PNG or JPG; no EPS with pdflatex.
- [ ] Comments stripped; no draft aids, secrets or identifying data.
- [ ] Size within current arXiv limits; ancillary files in `anc/`.
- [ ] Metadata form (title, authors, abstract, subject class, licence) prepared in plain text with no TeX that arXiv cannot render.
- [ ] After "Review Files", read the arXiv compile log and the generated PDF fully before announcing.

## 9. Common failures

| Symptom on arXiv | Likely cause | Fix |
|---|---|---|
| `File 'x.sty' not found` | A package present locally is not in arXiv's TeX Live | Include the `.sty` in the package |
| Citations show as `?` | `.bbl` missing or not matching the main file name | Upload `main.bbl` from the same build |
| `Patching \MakeUppercase failed` | Old `biblatex.sty` in the package | Delete the local copy |
| Wrong `.bbl` format version warning | `.bbl` made by another biblatex release | Rebuild with the selected TeX Live |
| Figure not found | Case mismatch or extension absent for the chosen route | Match case; convert format |
| Wrong main file compiled | Several `.tex` files at root | Mark `toplevel` in `00README.json` |
| Compiles locally, fails on arXiv | Different TeX Live year | Choose the same year; avoid unreleased package features |
| `\write18` or shell-escape errors | Package needs shell access | Pre-render outputs and include the files |
