# Testing Solana Programs

LiteSVM in Rust and TypeScript, Mollusk for single-instruction and compute-unit tests, Surfpool for local networks, and which negative tests every program needs. The Rust test builds with `cargo test --no-run` against anchor-lang 1.2.2 and the LiteSVM 0.15.0 dependency set that `anchor init` pins; the TypeScript test type-checks against litesvm 1.6.1 and `@solana/kit` 8.6.0. Both load `target/deploy/vault.so`, so run `anchor build` first.

## Choosing a harness

| Tool | Runs | Best for |
|---|---|---|
| LiteSVM (`litesvm` crate, `litesvm` npm, `solders.litesvm` in Python) | Compiled `.so` in an in-process SVM | Default for program tests: fast, deterministic, can set accounts, clock and sysvars |
| Mollusk (`mollusk-svm`) | One instruction (or a chain) against explicit accounts | Unit tests of handlers, compute-unit regression checks |
| Surfpool | A local network, optionally forking mainnet state | End-to-end tests with real RPC, wallets and clients; `anchor test` default |
| `solana-test-validator` | A full local validator | Legacy setups; slower |
| `solana-bankrun` | Deprecated; its README points to LiteSVM | Migrate existing suites |

`anchor init` generates LiteSVM Rust tests by default (`--test-template litesvm`); `mollusk`, `rust`, `mocha` and `jest` templates also exist.

## LiteSVM in Rust

Cargo dev-dependencies as generated by `anchor init` for Anchor 1.2.2 (its `Cargo.lock` pins a dependency graph that builds on Rust 1.89):

```toml
[dev-dependencies]
litesvm = "0.15.0"
solana-message = "4"
solana-transaction = "4"
solana-signer = "3"
solana-keypair = "3"
```

Newer LiteSVM releases (0.18.x at the time of writing) follow newer Agave crates and may need a newer Rust toolchain and matching `solana-*` versions; upgrade them together.

```rust
use anchor_lang::{
    prelude::Pubkey,
    solana_program::{instruction::Instruction, system_program},
    AccountDeserialize, InstructionData, ToAccountMetas,
};
use litesvm::LiteSVM;
use solana_keypair::Keypair;
use solana_message::{Message, VersionedMessage};
use solana_signer::Signer;
use solana_transaction::versioned::VersionedTransaction;

const SO: &str = concat!(env!("CARGO_MANIFEST_DIR"), "/../../target/deploy/vault.so");

fn pdas(owner: &Pubkey) -> (Pubkey, Pubkey) {
    let state = Pubkey::find_program_address(&[vault::STATE_SEED, owner.as_ref()], &vault::ID).0;
    let vault = Pubkey::find_program_address(&[vault::VAULT_SEED, owner.as_ref()], &vault::ID).0;
    (state, vault)
}

fn send(svm: &mut LiteSVM, payer: &Keypair, ix: Instruction) -> litesvm::types::TransactionResult {
    let msg = Message::new_with_blockhash(&[ix], Some(&payer.pubkey()), &svm.latest_blockhash());
    let tx = VersionedTransaction::try_new(VersionedMessage::Legacy(msg), &[payer]).unwrap();
    svm.send_transaction(tx)
}

fn setup() -> (LiteSVM, Keypair) {
    let mut svm = LiteSVM::new();
    svm.add_program_from_file(vault::ID, SO).unwrap();
    let owner = Keypair::new();
    svm.airdrop(&owner.pubkey(), 10_000_000_000).unwrap();
    let (state, vault_pda) = pdas(&owner.pubkey());
    let ix = Instruction::new_with_bytes(
        vault::ID,
        &vault::instruction::Initialize {}.data(),
        vault::accounts::Initialize { owner: owner.pubkey(), state, vault: vault_pda, system_program: system_program::ID }
            .to_account_metas(None),
    );
    send(&mut svm, &owner, ix).unwrap();
    (svm, owner)
}

fn move_ix(name: &str, owner: &Pubkey, signer: &Pubkey, amount: u64) -> Instruction {
    let (state, vault_pda) = pdas(owner);
    let data = match name {
        "deposit" => vault::instruction::Deposit { amount }.data(),
        _ => vault::instruction::Withdraw { amount }.data(),
    };
    let mut metas = vault::accounts::Move { owner: *owner, state, vault: vault_pda, system_program: system_program::ID }
        .to_account_metas(None);
    metas[0].pubkey = *signer; // lets a test substitute the signer
    Instruction::new_with_bytes(vault::ID, &data, metas)
}

#[test]
fn deposit_then_withdraw() {
    let (mut svm, owner) = setup();
    send(&mut svm, &owner, move_ix("deposit", &owner.pubkey(), &owner.pubkey(), 1_000_000_000)).unwrap();

    let (state, vault_pda) = pdas(&owner.pubkey());
    let data = svm.get_account(&state).unwrap().data;
    let parsed = vault::VaultState::try_deserialize(&mut data.as_slice()).unwrap();
    assert_eq!(parsed.total, 1_000_000_000);
    assert_eq!(svm.get_balance(&vault_pda), Some(1_000_000_000));

    svm.expire_blockhash();
    send(&mut svm, &owner, move_ix("withdraw", &owner.pubkey(), &owner.pubkey(), 1_000_000_000)).unwrap();
}

#[test]
fn another_signer_cannot_withdraw() {
    let (mut svm, owner) = setup();
    send(&mut svm, &owner, move_ix("deposit", &owner.pubkey(), &owner.pubkey(), 1_000_000_000)).unwrap();

    let attacker = Keypair::new();
    svm.airdrop(&attacker.pubkey(), 1_000_000_000).unwrap();
    // Seeds use the signer's key, so the owner's state PDA no longer matches.
    let res = send(&mut svm, &attacker, move_ix("withdraw", &owner.pubkey(), &attacker.pubkey(), 1));
    assert!(res.is_err());
}
```

Useful LiteSVM controls: `set_account` to plant arbitrary state (forged accounts for owner-check tests), `warp_to_slot` and `set_sysvar(&clock)` (Rust) or `setClock` (TypeScript) for time, `expire_blockhash` to send identical instructions twice, `with_sigverify(false)` only when a test needs it.

## LiteSVM in TypeScript (Kit)

```ts
import assert from "node:assert/strict";
import { createHash } from "node:crypto";
import { test } from "node:test";
import { FailedTransactionMetadata, LiteSVM } from "litesvm";
import { SYSTEM_PROGRAM_ADDRESS } from "@solana-program/system";
import {
  AccountRole,
  address,
  appendTransactionMessageInstruction,
  createTransactionMessage,
  generateKeyPairSigner,
  getAddressEncoder,
  getProgramDerivedAddress,
  getU64Encoder,
  lamports,
  pipe,
  setTransactionMessageFeePayerSigner,
  signTransactionMessageWithSigners,
  type Address,
  type Instruction,
  type KeyPairSigner,
} from "@solana/kit";

const PROGRAM_ID = address("6J3hLLkJAia6JAE5aQeHiGGbLS6HViBbJ1CxffB4uh25");
const disc = (n: string) => createHash("sha256").update(`global:${n}`).digest().subarray(0, 8);
const pda = async (seed: string, owner: Address) =>
  (await getProgramDerivedAddress({ programAddress: PROGRAM_ID, seeds: [seed, getAddressEncoder().encode(owner)] }))[0];

async function ix(name: string, owner: Address, amount?: bigint): Promise<Instruction> {
  const data = amount === undefined ? disc(name) : new Uint8Array([...disc(name), ...getU64Encoder().encode(amount)]);
  return {
    programAddress: PROGRAM_ID,
    accounts: [
      { address: owner, role: AccountRole.WRITABLE_SIGNER },
      { address: await pda("state", owner), role: AccountRole.WRITABLE },
      { address: await pda("vault", owner), role: AccountRole.WRITABLE },
      { address: SYSTEM_PROGRAM_ADDRESS, role: AccountRole.READONLY },
    ],
    data,
  };
}

async function send(svm: LiteSVM, payer: KeyPairSigner, instruction: Instruction) {
  const tx = await pipe(
    createTransactionMessage({ version: 0 }),
    (m) => setTransactionMessageFeePayerSigner(payer, m),
    (m) => svm.setTransactionMessageLifetimeUsingLatestBlockhash(m),
    (m) => appendTransactionMessageInstruction(instruction, m),
    (m) => signTransactionMessageWithSigners(m),
  );
  return svm.sendTransaction(tx);
}

test("owner deposits and withdraws; the vault keeps the lamports", async () => {
  const svm = new LiteSVM();
  svm.addProgramFromFile(PROGRAM_ID, "target/deploy/vault.so");
  const owner = await generateKeyPairSigner();
  svm.airdrop(owner.address, lamports(10_000_000_000n));

  assert.ok(!((await send(svm, owner, await ix("initialize", owner.address))) instanceof FailedTransactionMetadata));
  const res = await send(svm, owner, await ix("deposit", owner.address, 1_000_000_000n));
  assert.ok(!(res instanceof FailedTransactionMetadata), String(res));
  assert.equal(svm.getBalance(await pda("vault", owner.address)), lamports(1_000_000_000n));

  svm.expireBlockhash();
  assert.ok(!((await send(svm, owner, await ix("withdraw", owner.address, 1_000_000_000n))) instanceof FailedTransactionMetadata));
  assert.equal(svm.getBalance(await pda("vault", owner.address)) ?? lamports(0n), lamports(0n));
});

test("a withdrawal above the recorded total fails", async () => {
  const svm = new LiteSVM();
  svm.addProgramFromFile(PROGRAM_ID, "target/deploy/vault.so");
  const owner = await generateKeyPairSigner();
  svm.airdrop(owner.address, lamports(10_000_000_000n));
  await send(svm, owner, await ix("initialize", owner.address));
  const res = await send(svm, owner, await ix("withdraw", owner.address, 1n));
  assert.ok(res instanceof FailedTransactionMetadata);
});
```

The npm package (1.x) takes Kit types (`Address`, Kit transactions) and depends on `@solana/kit` 8.x; older 0.x releases used web3.js 1.x types. A new `LiteSVM()` includes core programs such as the System Program and SPL Token.

## Mollusk

```rust
use mollusk_svm::{program::keyed_account_for_system_program, result::Check, Mollusk};

let mollusk = Mollusk::new(&vault::ID, "vault"); // loads target/deploy/vault.so
let result = mollusk.process_and_validate_instruction(
    &instruction,
    &[(owner, owner_account), (state, state_account), (vault_pda, vault_account), keyed_account_for_system_program()],
    &[Check::success()],
);
println!("CU used: {}", result.compute_units_consumed);
```

- Accounts are passed explicitly as `(Pubkey, Account)` pairs, which makes forged-account tests direct.
- Use `Check::compute_units(n)` or compare `compute_units_consumed` to a stored baseline to catch CU regressions in CI.
- Anchor's Mollusk template gates tests behind a `test-sbf` feature; check the generated `Cargo.toml` for the exact setup.

## Negative tests every program needs

| Attack or bug | Test |
|---|---|
| Missing signer | Send with the authority account not signing (or another signer substituted) and expect failure |
| Missing owner check | `set_account` a look-alike account owned by another program and pass it |
| Wrong PDA | Pass another user's PDA; pass a PDA derived with a non-canonical bump |
| Type confusion | Pass an account of a different `#[account]` type with a compatible layout |
| Arithmetic | `u64::MAX` amounts, zero amounts, amounts that cross rent-exempt thresholds |
| Duplicate accounts | Pass the same account in two mutable positions |
| Close and revive | Close an account, then try to use or re-init it in the same and the next transaction |
| CPI substitution | Pass a fake program in a `Program` or `Interface` slot |
| Token-2022 mint | Use a mint with a transfer fee or hook if the program claims Token-2022 support |

Assert the specific Anchor error (custom codes start at 6000; constraint errors have fixed codes) rather than only `is_err()` once the suite is stable.

## CI

- `anchor build` then `cargo test` (Rust) or the configured TS script; cache `~/.cargo`, `target/` and the platform tools.
- Run `anchor build --verifiable` on release branches and compare the hash with the deployed program.
- Track compute units per instruction and fail on regressions.
- Fuzz handlers that take numeric input (Anchor documents fuzzing options; check the current docs for maintained tools).
